# 特別な配慮を要する幼児児童生徒 指導支援ハンドブック

校内向けの指導支援ハンドブックで、2冊構成です（版4.0.0〜）。

- **特別支援ガイドブック** … 障害種別・原因疾患ごとの教育的ニーズと支援（文部科学省「障害のある子供の教育支援の手引」）、特別の教育課程（日本語指導・特異な才能と障害を併せ有する児童生徒）、自立活動（解説 自立活動編）
- **指導提要ガイドブック** … 生徒指導提要 第II部の各課題（不登校、ヤングケアラー、以後順次）

住み分けの線は「教育課程で応えるか、生徒指導で応えるか」です。日本語指導と特異な才能は特別の教育課程という教育課程上の枠組みで応えるので特別支援側、ヤングケアラーは提要第13章の家庭状況なので指導提要側にあります。2冊の間は、指導提要側の各課題が持つ「関連する障害種別」と、それを逆引きして障害種別ページに出す「関連する生徒指導上の課題・特別の教育課程」でつながります。自立活動との関係は対応表ではなく、サポートシートの手順を経由します。

旧名称「特別支援教育 指導支援ハンドブック」（〜版3.2.4）、「特別な配慮を要する児童生徒 指導支援ハンドブック」（〜版4.4.6）。版4.4.7から「幼児児童生徒」。本ツール自身の文では「幼児児童生徒」と書き、法令・通知・様式の名称と「」で引用した語（不登校児童生徒、児童生徒理解・支援シート、特定分野に特異な才能のある児童生徒など）は原文どおり「児童生徒」のまま。URL（リポジトリ名 `tokushi_Guidebook`）は据え置きです。

公開先: https://backtree-create.github.io/tokushi_Guidebook/

## 出典の扱い（先に読んでください）

このツールの内容は、性質の異なる3種類が混ざっています。編集するときは、どれを触っているのかを意識してください。

| 区分 | 内容 | 出典 |
|---|---|---|
| 障害種別ページ | 教育的ニーズ／指導内容／合理的配慮／学びの場 | 文部科学省「障害のある子供の教育支援の手引」（令和3年6月） |
| 自立活動 6区分27項目 | 区分・項目・内容の要旨 | 文部科学省「解説 自立活動編」（平成30年3月） |
| **疾患・状態別の分類（495件）** | 医学的説明は公的疾患データベース由来。**支援内容は本ツールによる教育的整理** | 文部科学省の資料に直接記載されているものではありません |

3つ目が全体の分量の大半を占めます。各疾患を開くと、記述ごとの出典区分がバッジで表示されます。

## 編集のしかた

### 内容を直す

ルート直下の JSON を直接編集します。`index.html` に内容は書かれていません。

編集したら **必ず** 次を実行してください。

```bash
node validate.mjs   # 整合性チェック
node build.mjs      # 配布用の単一ファイルを作り直す
```

**GitHub のサイト上で編集した場合は、これらを自分で実行する必要はありません。**
`build.yml` が push のたびに検査とビルドを行い、配布用ファイルを自動でコミットします。

`validate.mjs` は次を見ています。

- 疾患に書かれた自立活動の項目名が、27項目と一字一句一致しているか（**タイポしても画面上は静かに表示されるだけなので、これが唯一の防波堤です**）
- `sourceId` が `sources.json` に存在するか
- 区分内で病名が重複していないか
- `sw.js` の `VERSION` と `meta.json` の `version` が揃っているか
- `sw.js` の `PRECACHE` に疾患ファイルの記載漏れがないか
- 全ファイル名が一意か（同名だとアップロード時に衝突するため）
- 文字色のコントラスト比が役割ごとの下限を満たすか、文字サイズが 11px 以上か
- 明るい地に金（`--gold`）を使っていないか

### 配色の決まり

行政機関のサイトに置かれても違和感がないよう、白地・濃紺・藍の3色で組んでいます。**この骨格は崩さないでください。**

| 役割 | 色 | 使う場所 |
|---|---|---|
| 地 | 白 `--paper` | ページ全体。生成りやクリーム色は使わない |
| 副次的な面 | `--paper2` `#f2f5f8` | わずかに青みを帯びた明るいグレー |
| 構造色 | 濃紺 `--navy` `#132132` | ヘッダー、見出しの罫、選択状態 |
| 操作色 | 藍 `--accent` `#0f4c8a` | リンク、押せるもの |
| 金 | `--gold-soft` `--gold-line` | **濃紺の面の上だけ。** 明るい地に置くと濁って見える |

`--gold` は廃止しました。明るい配色で `var(--gold)` を書くと `validate.mjs` が落ちます。

### 文字色の下限

一律 4.5 では「基準は満たすが沈んで見える」配色を通してしまうため、役割ごとに下限を分けています。

| トークン | 下限 | 現在（白地） |
|---|---|---|
| `--ink` 本文 | 12 | 18.0 |
| `--ink-strong` 見出し | 12 | 16.5 |
| `--ink-soft` 補助 | 7 | 9.3 |
| `--ink-faint` 注記 | 5.5 | 6.2 |
| `--accent` リンク | 4.5 | 8.7 |

バッジの `--tone-*-fg` / `--tone-*-bg`、`--tag-fg` / `--tag-bg` は 4.5 以上。`font-size` は 11px 以上。**明るい配色・暗い配色の両方**を `validate.mjs` が検査します。

薄いグレーや小さい文字は画面上では洗練されて見えますが、教室のプロジェクターや明るい部屋では読めません。色を変えたいときは、色相はそのままに明度だけ動かしてください。

### 動作を確認する

`index.html` をダブルクリックしても **動きません**（`fetch` が CORS で止まります）。ローカルサーバー経由で開いてください。

```bash
python3 -m http.server 8000
# → http://localhost:8000/
```

単一ファイル版（`tokushi-guidebook-standalone.html`）はダブルクリックで開けます。

### 内容を更新したときのチェックリスト

1. 該当する JSON を編集
2. `meta.json` の `updated` を今日の日付に、`version` を上げる
3. **`sw.js` の `VERSION` を `version` と同じ値に**（揃っていないと `validate.mjs` が落ちます）
4. `meta.json` の `changelog` に1行足す
5. `node validate.mjs && node build.mjs`（サイト上で編集した場合は不要）
6. コミット・プッシュ

## Service Worker について

**HTML と JSON はネットワーク優先**、CSS/JS/画像はキャッシュ優先です。

これは意図的な設計です。以前の版はすべてキャッシュ優先かつキャッシュ名が固定だったため、一度開いた端末には更新内容が二度と届かない状態でした。現場で参照される資料でこれが起きると、古い情報が独り歩きします。

`VERSION` を変えると、`activate` 時に古いキャッシュが破棄されます。**内容を更新したら必ず `VERSION` も更新してください。**

## 参考資料の管理

URL は `sources.json` にのみ書きます。画面のフッターと「出典・リンク集」タブは、このファイルから自動生成されます。

各資料には更新方針を持たせています。

- `"policy": "pinned"` — 特定版の引用。令和3年6月の手引など。更新不要
- `"policy": "latest"` — 常に最新を参照すべき資料。年報・年次調査など

**リンクチェックは「生きているが年度が古い」を検出できません。** 旧年度のページは残り続けるからです。そのため `policy: "latest"` の資料は、毎年3月に GitHub Actions が見直し用の Issue を自動で立てます。

### 自動化されているもの

| ワークフロー | 実行時期 | 内容 |
|---|---|---|
| `validate.yml` | push / PR ごと | データ整合性チェック、ビルド確認、URLの書式確認 |
| `build.yml` | JSON 等の変更時 | 配布用の単一ファイルを再生成して自動コミット |
| `linkcheck.yml` | 毎月2日 ＋ `sources.json` の変更時 | URL の到達性確認。切れていたら Issue を作成／更新し、直ったら自動で閉じる |
| `source-watch.yml` | 毎月15日 | `policy: latest` の一覧ページのハッシュを比較し、中身が変わっていたら Issue |
| `annual-review.yml` | 毎年3月1日 | `policy: latest` の資料を人の目で見直す Issue |

資料が古くなる形は3つあり、それぞれ受け持ちが違います。**消えた**のは `linkcheck.yml`、**中身が新版に差し替わった**のは `source-watch.yml`、**生きているが今は別の資料のほうが適切**は人にしか判断できないので `annual-review.yml` が年に一度うながします。

重要な PDF は [web.archive.org の Save Page Now](https://web.archive.org/save) に手動保存しておくことをおすすめします。mext.go.jp は PDF の URL をよく変えます。

### 自動化についての決まりごと

- **ワークフローを差し替えるときは、必ず「置き換え」にしてください。** GitHub のサイト上でファイルを開いて編集する方法だと、既存の中身を消さずに貼り付けたときに**後ろに足されてしまい**、`Invalid workflow file`（'name' is already defined 等）になって全部の実行が失敗します。安全なのは次の手順です。

  1. リポジトリで `.github` → `workflows` フォルダを開く
  2. **Add file → Upload files**
  3. 5本の `.yml` をまとめてドラッグして Commit

  同じ名前のファイルは丸ごと差し替わるので、二重になりません。

- **各ワークフローの先頭と末尾に目印のコメントが入っています。** 末尾の「このファイルの末尾」より下に何かあれば、貼り付けが二重になっている合図です。その行から下をすべて消してください。

- **Issue は増やさず、書き換える。** 同じ表題の未解決 Issue があれば本文を最新の結果に差し替えます。毎月同じ Issue が積み上がると誰も読まなくなるためです。
- **`linkcheck.yml` は毎月コミットを残します**（`linkcheck-log.md`）。GitHub のスケジュール実行はリポジトリが60日間無活動だと止められるので、更新が途絶えても自動点検が生き続けるようにするためです。点検の記録そのものにもなります。
- **`source-hashes.json` と `linkcheck-log.md` は CI が書くファイルです。** 手で編集したり、zip から上書きしたりしないでください。台帳を消すと、次回すべてが「新規」になって変化を検知できなくなります。
- **CI が生成・追記するファイル**：`tokushi-guidebook-standalone.html`、`linkcheck-log.md`、`source-hashes.json`。

`#/jiritsu/<区分>/<項目>`（項目から疾患をたどる逆引き）と `#/c/futoukou` は版3.0.0で廃止しました。前者は一覧へ、後者は `#/seito/futoukou` へ転送します。旧 `#/haikei/*` は版4.0.0で `#/curriculum/*`（ヤングケアラーは `#/seito/young-carer`）へ転送します。

上段の切替（特別支援ガイドブック／指導提要ガイドブック）は、開いている画面がどちらの冊に属するかで自動で揃います。「出典・リンク集」は両冊で共有です。

ハッシュを使うのは、GitHub Pages でも単一ファイル版（`file://`）でもサーバ設定なしに同じ動きをするためです。検索はURLを打つたびに履歴を積まないよう、入力が止まってから置き換えます。

### 画面の構成とメニュー（版4.4.3〜）

`#/` は全体のホームで、「先生方へ」のお知らせ、2冊への入口カード、一次資料を置き、ここから特別支援ガイドブック（`#/guide`、障害種別の索引）と指導提要ガイドブック（`#/seito`）に分岐します。名称と「ホーム」はここに戻ります。

上は2段（名称と「趣意書（PDF）」「問い合わせ・情報提供」／「特別支援」「指導提要」の見出し付きでタブが1本の帯）。障害種別ガイドを開いているときだけ左に10区分の索引と検索欄が出ます。「先生方へ」のお知らせ、2冊の説明、一次資料はホームの本文の先頭にあり、文面は `meta.json` の `notice` で編集します。

右下の三本線ボタンで開く「メニュー」は、上の帯にある冊とタブの切替を繰り返しません。置いているのは次の4つです。

- **このページの中**：本文の見出し（`h3.block-title`）から自動で拾ったジャンプ。最大8つ
- **今いる冊の中の行き先**：特別支援側では「障害種別へ」（10区分）、指導提要側では「生徒指導上の課題へ」（9件）。今いる場所に印
- **道具**：特別支援側はサポートシート・計画シート・出典、指導提要側は計画シート（不登校の欄）・出典。続けて、もう一方の冊への入口
- **操作**：ページの先頭へ、ホーム、問い合わせ

外側を押すか Esc で閉じ、スマホでは画面下から出ます。ボタンは押すと×に変わり、パネルは右下から広がって項目が順に現れます。

### 疾患の詳細の出典表示（版4.2.6〜）

疾患を開くと、①概要（医学的説明）②個別に求められる支援 ③程度別の支援 の各見出しに「出典①」などの印が付き、末尾の「この項目の出典」欄が同じ番号で並びます。①は `basis.overview`（公的資料の区分と資料名・該当ページ）、②は `basis.support`（mext なら手引に記載、editorial なら本ツールの整理で、その旨の一文を自動で添える）、③は `severityScale.basis`（公的な尺度か本ツールの目安か）から出しています。校内から「個別に求められる支援がどの出典か初見で分からない」という指摘を受けて設けました。

### 出典の監視フラグ（版4.2.8〜）

`sources.json` の各出典に2つの任意フィールドがあります。

- `watch: "quiet"` … 月次の source-watch はハッシュを台帳に記録するが Issue には載せない。お知らせの更新で毎月中身が変わる一般向けポータル向け。年次の annual-review が「静かに監視している資料」として一覧するので、年1回は必ず目に入る。本文がそのページの特定の記述に依存するようになったら外す。分類・尺度の資料（ILAE、横地、Ross など）と文科省の通知一覧ページには付けない
- `kind: "portal"` … 版という概念がない常時更新のページ・データベース・法令。annual-review の「版の記載がないもの」から除外する

`validate.mjs` は、`watch` が quiet 以外、`kind` が portal 以外、`watch: quiet` が latest 以外の出典に付いている場合をエラーにします。

### 画面の文言の方針（版4.2.4〜）

画面に出す文は「何があり、どう使うか」だけにします。版番号、ファイル名、内部の仕組み（validate や sources.json）、変更の経緯（「版3.0.0で廃止」「以前は〜にあった」）は README と changelog に書き、画面には出しません。読む人にとって、経緯は判断の材料にならないためです。メンテナンス中の案内も、理由の詳細ではなく「整えている」ことと再開の目安だけを出します。

### 画面を移ったときのスクロール（版4.2.3〜）

画面の最上部には戻しません。ヘッダーとお知らせ枠が長いので、毎回そこまで戻すと使いにくいためです。

- 自分で押して別の画面に移ったとき：本文の先頭（タブの直下）が見えるところまで。すでに見えていれば動かさない。スマホ幅で障害種別ページを開いたときは、索引の下にある本文の先頭まで
- 疾患を開いた／閉じたとき：動かさない。画面は描き直さず、URLだけ差し替える。開いた詳細が画面の外にはみ出すときだけ最小限寄せる
- 戻る／進む：離れたときの位置に戻す（`history.scrollRestoration = 'manual'` にして、ブラウザ任せの復元と競合させない）
- 検索の入力、出典ページ内のジャンプ：従来どおり

### 特別の教育課程（日本語指導・2E）

特別支援ガイドブックの中のタブで、日本語指導が必要な児童生徒と、特異な才能と障害を併せ有する児童生徒（2E）の2件を扱います。設計上の決めごとは次のとおりです。

- **自立活動27項目とは対応付けない。** 一覧の冒頭で、特別の教育課程が3種類（通級による指導＝施行規則第140条・141条、日本語指導＝第56条の2等、特異な才能＝検討中）あり、自立活動を用いるのは通級（障害）だけであることを明示しています。`related` で既存の区分へ内部リンクし、見立ての重なりを確認する入口にしています
- **一次資料は公的資料に限る。** 文部科学省の手引、通知、審議会資料まで。学術研究は本文の根拠にしません
- **2Eは制度化の直前。** 中教審ワーキンググループの取りまとめ案（「案」の付かない最終版は未掲載）に基づくため、`status.tone` を `warn` にし、最終版や運用の手引きが出たら本文を見直します
- **山口県固有の情報（入試の特別措置、相談窓口）は載せない。** 自治体により異なる旨だけ書きます

1件のフィールドは、`status`（制度の状況）／`basis`（公的な位置づけ。各行に `sourceId` を付けられる）／`overview`／`points`（押さえておきたい点）／`framework`（任意。2Eの制度の骨子）／`signs`／`supports`（見出し付きのグループ）／`planning`（任意）／`related`（区分idと一言）／`relatedTopics`（他の主題への横リンク）／`sources`／`reviewed` です。`validate.mjs` は必須項目、出典IDと区分IDの実在、本文に「要確認」「TODO」が残っていないことを検査します。

2EのWGトップページは `sources.json` で `policy: latest` にしてあり、月次の source-watch が変化を検知して Issue にします。

### 自立活動の扱い（対応付けの廃止とサポートシート）

かつて本ツールは、疾患・状態495件と障害種10区分のそれぞれに自立活動27項目の「候補」を付けていました。すべて手引にも自立活動編解説にも記載のない編集上の整理で、校内から「対応付けを鵜呑みにして個別の指導計画に転記する人が出る」という指摘がありました。版3.0.0で逆引きを廃止し、版3.2.0で対応付けそのものをデータごと廃止しました（旧データはGitの履歴に残っています）。

理由は、自立活動編解説の手順（実態把握 → 課題の整理 → 項目の選定 → 具体的な指導内容）では、項目は目の前の子どもの実態から選ぶもので、疾患や障害種から引くものではないからです。`validate.mjs` は、区分・疾患に `jiritsu` が戻っていないことを検査します。

代わりに置いたのが「自立活動サポートシートをAIと考える」（`#/jiritsu/support`、一覧タブの上部から）です。版4.2.1で「教員が①〜④を全部書いてから相談する」形をやめ、「困っていることを一言書くと、AIが手順に沿って聞き出す」形にしました。①〜④を書ける教員は最後まで一人で考えられる、という校内の指摘によるものです。

- 入力は「今、困っていること」（1〜3行）だけ。校種・主たる障害・特に相談したいことは任意
- 指示書は、AIを「聞き取り、問い返す人」に固定する。①実態把握（4観点）→ ②6区分の観点（関係しそうなものだけ）→ ③課題の整理 → ④中心となる課題と指導目標 を、1回に1問、答えを要約して確認しながら聞き出す（目安5〜8往復）。教員が「分からない」と答えた事項は推測で埋めず、最後の「確認すべき点」に残す
- ④まで揃ってから ⑤項目の選定 → ⑥関連付け → ⑦具体的な指導内容 を提案。項目は27項目の正式名称だけ、各行に根拠、入力にない前提は「仮定」と明示、シートの冒頭に①〜④の要約を付ける
- 従来の①〜④の欄は「書けるところまで書いておく（任意）」として折り畳み。書いてある欄はAIが聞き直さない
- Copilot 用は正式名称のみで短く、Gemini 用は要旨付き。氏名の欄は置かず「本児」で書く。入力はブラウザ内だけで組み立て、送信も保存もしない

サイトの中でAIを直接動かしていないのは、静的サイトにAPIキーを置けないことと、子どもの実態を外部APIに送らないためです。所見文・個別の指導計画のプロンプトメーカーと同じ方式です。

### 検索避け

校内向けのため、検索エンジンの索引に載せない設定にしています。

- `robots.txt`（ルート直下）で全体のクロールを拒否
- `index.html` の `<meta name="robots" content="noindex, nofollow, noarchive">`。単一ファイル版にも `build.mjs` を通じて同じものが入る
- `validate.mjs` が両方の有無を検査する

限界：`about.pdf` には meta タグを入れられないので robots.txt の拒否だけが効きます。GitHub Pages では HTTP ヘッダー（X-Robots-Tag）は設定できません。リポジトリ自体（github.com）は公開リポジトリである限り検索に出ます。

### メンテナンス中の表示（改修中の箇所を覆う）

改修が終わるまで、該当箇所を「メンテナンス中」の案内で覆えます。`meta.json` の `maintenance` を書き換えるだけで、コードは触りません。

```json
"maintenance": {
  "support": {
    "on": true,
    "label": "自立活動サポートシート（AIと考える）",
    "place": "上部タブ「自立活動 6区分27項目 一覧」→ 上部のカード → サポートシートのページ",
    "scope": "ページ全体",
    "title": "案内の見出し", "note": "理由", "until": "再開の目安"
  },
  ...
}
```

| キー | 何が | どこに | 覆われる範囲 |
|---|---|---|---|
| `site` | サイト全体 | すべての画面 | 中身がすべて案内に置き換わる。他の5つより優先。ヘッダーとお知らせ枠は見える |
| `support` | 自立活動サポートシート | 一覧タブ → 上部のカード → ページ | ページ全体 |
| `sheet2` | 計画シート | 特別支援ガイドブックのタブ「計画シート」 | タブ全体 |
| `jiritsu-block` | 障害種別ページの自立活動の欄 | 障害種別ガイド → 各障害種のページ | その欄だけ |
| `curriculum` | 特別の教育課程 | 特別支援ガイドブックのタブ | タブ全体（一覧と2件）。タブのラベルにも印 |
| `seito` | 指導提要ガイドブック | 上段の切替 | 冊全体（一覧と各課題）。タブのラベルとホームの案内枠にも印。障害種別ページの逆引きも出さない |
| `links` | 目的別リンク | 出典・リンク集タブの上部 | 目的別リンクだけ（対応表と資料一覧は見える） |

`label`（呼び名）・`place`（場所）・`scope`（範囲）は編集者向けのメモで、画面には出ません（読む人にどこが整備中かの一覧は見せない方針）。画面に出るのは `title`・`note`・`until` だけです。`validate.mjs` は3つのメモが欠けているとエラーにします。

覆ったまま中身を確認するには、URLの末尾に `?preview=合言葉` を付けて開きます（例：`https://backtree-create.github.io/tokushi_Guidebook/?preview=xxxx#/seito`）。合言葉は `maintenance.previewKey` で、8文字以上。合言葉が合うと、そのブラウザのタブでは覆いが外れ、画面上部に「プレビュー表示中」の帯が出ます。帯の「解除」で元に戻り、別のタブや別の端末には影響しません。合言葉はURLからすぐ消されるので、共有される心配は小さいですが、厳密な認証ではありません（公開前の下書きを自分で見る用途です）。

全機能を一度に止めたいときは `site` だけを `true` にします（他のキーはそのままでよい）。再開するときは `site` を `false` に戻すと、個別のスイッチの状態に戻ります。

`on` を `false` にすれば即元に戻ります。`validate.mjs` は、知らないキー、`on` が真偽値でないもの、`on` なのに `title` がないものをエラーにします。版を上げる必要はありませんが、CSSやJSを変えていない場合でも `meta.json` の変更で build は走ります。

### 計画シート（2階シート 試作）（版4.3.0〜）

`#/plan`（特別支援ガイドブックのタブ「計画シート」。版4.3.2で自立活動タブから分離。旧 `#/jiritsu/sheet2` は転送）。通級・日本語指導・不登校・特異な才能の各特例の計画を、「共通シート」＋「特例ごとの個別シート」の構成で一枚にまとめる様式です。中教審ワーキンググループの取りまとめ案が示す構成に沿った試作で、国の参考様式が公表されたら欄を合わせ直します。

- 共通シート（校種・学年、対象期間、実態の概要、得意・興味、本人・保護者の希望、共通の目標、支援体制、見直し、引継ぎ）
- 個別シートは該当する特例だけを選んでタブで切替。欄の根拠は、通級＝自立活動編解説の手順、日本語指導＝文部科学省の個別の指導計画作成参考資料、不登校＝令和元年通知の児童生徒理解・支援シート、特異な才能＝取りまとめ案の指導計画の記載項目例
- 出力は印刷（PDF保存。選んだ特例だけを表に）と、Wordに貼る用のテキストのコピー。入力はブラウザ内だけで、送信・保存はしない。氏名の欄は置かない
- **AIと考える**（版4.3.1〜）：困っていることを一言書くと、サポートシートと同じ方式で Copilot／Gemini 向けの指示書ができる。AIは「聞き取り、問い返す人」として1回1問で聞き出し、共通シート→個別シートの順に整理し、最後に「【共通シート】／■ 欄名／内容」の形式（このページのコピー形式と同じ）で出す。その回答を貼り付けると欄に流し込める（見出し【…】で共通／個別を区別し、■ の欄名で照合。読み取れない欄名は無視、上書きは確認付き）。通級を選ぶと自立活動の27項目の正式名称を同梱し、障害名から項目を引かないよう指示する
- 欄の定義は `app.js` の `S2_COMMON` と `S2_SPECIAL` にまとめてあり、国の様式に合わせるときはそこだけ直す。指示書の欄の定義も同じ配列から作るので、欄を変えれば指示書も追従する
- メンテナンス中のキーは `sheet2`

### 出典・リンク集（目的別リンク）

「リンクが見にくい」「○○についてはここから、という一覧が欲しい」という校内の声を受けて、版3.1.0で「診断名・出典」タブを「出典・リンク集」に改めました。上部に目的別の案内（`links.json`、10群）を置き、診断名の対応表と参照資料の一覧はその下に残しています。ページ先頭のボタンで各節へ飛べます。

`links.json` の決まりごとは次のとおりです。

- **URLを書かない。** 各行は `sourceId`（`sources.json` の id）、`route`（本ツール内のハッシュ、例 `#/seito/futoukou`）、`anchor`（出典ページ内の節 `termmap` / `srclist` / `research`）のどれか1つを持ちます。URLの管理が二重にならないためで、`validate.mjs` が `url` を書くとエラーにします
- `route` は実在する画面でなければ通りません。`sourceId` は `sources.json` に、`route` は区分・主題の id に照合します
- 群の追加は `links.json` に `{ id, title, lead, items }` を足すだけです。新しい資料を案内したいときは、先に `sources.json` に登録してから id で参照してください

あわせて、文中のリンク（出典の箱、資料の一覧、主題ページの根拠）の下線を太くし、別タブで開く外部リンクに ↗ を付けました。カード型のリンク（区分・主題のカード）は従来どおり下線なしです。

### 指導提要ガイドブック（生徒指導上の課題）

生徒指導提要（令和4年12月改訂）第II部「個別の課題に対する生徒指導」を一次資料とする冊で、提要の章の順に並べます（`chapter` フィールド）。第I部（生徒指導の基礎・体制）は載せません。第II部の10章をすべて反映しています（9件）。いじめ（第4章）、暴力行為・少年非行（第5・6章を1件に統合）、児童虐待（第7章）、自殺予防（第8章）、中途退学（第9章）、不登校（第10章）、インターネット・SNS（第11章）、性に関する課題（第12章）、ヤングケアラー（第13章 支援を要する家庭状況）。第13章の発達障害・精神疾患・健康課題は障害種別ガイドと重複するため独立した項目にせず、各課題の「関連する障害種別」で扱います。児童虐待と自殺予防は「気づいて、つなぐ／守る」対象なので `planning` を持ちません（`validate.mjs` が検査）。自殺予防の本文には方法・手段に関する記述を置かず、事後対応でも「方法の詳細を伝えない」と明記しています。データの型は `curriculum.json` と同じです。

設計上の決めごとは、自立活動と対応付けない、公的資料に限る、`related` で障害種別へ、`relatedTopics` で他の主題へ内部リンクする、の4つ。ヤングケアラーのように「指導」ではなく「気づいて、つなぐ」対象は `planning` を持たせず、`supports` を「校内での初動」「外部連携」の構成にします（`validate.mjs` が `young-carer` に `planning` があるとエラーにします）。

各課題ページには「障害のある児童生徒がこの課題に直面している場合の自立活動」として、課題名から項目を引くのではなくサポートシートの手順で決める旨の導線を1つ置きます。対応表は置きません。

不登校について、旧 `futoukou.json` の19の類型（神経症的不登校、無気力型など）は一次資料が確認できなかったため引き継がず、提要の重層的支援構造（発達支持的／課題未然防止教育／課題早期発見対応／困難課題対応的）、教育機会確保法と基本指針、令和元年通知（児童生徒理解・支援シート、出席扱い）、COCOLOプランの枠組みで書き直しました。不登校児童生徒数などの数値は本文に固定せず、`mext-mondai-kodo`（policy latest）の最新版を参照するよう書いています。

**障害種別ページへの逆引き。** 各課題の `related` を逆から引き、障害種別ページの「学びの場」の下に「関連する生徒指導上の課題・特別の教育課程」を自動で出します。データを二重に持たないための仕組みで、指導提要側が覆われている間は出しません。

## 程度別の支援

### 法令が定める障害の程度

`categories.json` の `legalCriteria` に、**学校教育法施行令 第22条の3** の条文を収録しています。視覚障害・聴覚障害・知的障害・肢体不自由・病弱の5区分が対象です（言語障害・自閉症・情緒障害・LD・ADHD・不登校はこの政令の対象外なので入っていません）。

**条文は要約せず、原文のまま引用してください。** 言い換えると意味が変わります。`validate.mjs` は `law` `term` `clauses` `sourceId` `note` が揃っているかを検査します。`note`（就学先を決めるものではない旨）は必須です。

### 特別支援学級・通級による指導の程度

施行令第22条の3は**特別支援学校**の基準です。特別支援学級と通級による指導は別で、**25文科初第756号 通知（平成25年10月4日）の別紙**が定めています。これを `categories.json` の `programCriteria` に収録しています。

```json
"programCriteria": {
  "notice": "平成25年10月4日付け25文科初第756号 文部科学省初等中等教育局長通知（別紙）",
  "sourceId": "mext-756",
  "entries": [
    { "program": "特別支援学級", "term": "弱視者", "text": "拡大鏡等の使用によつても…" },
    { "program": "通級による指導", "term": "弱視者", "text": "拡大鏡等の使用によつても…" }
  ],
  "note": "特別支援学級・通級による指導の対象となる障害の程度として、国が示した目安です。…"
}
```

収録したのは不登校を除く10区分です。区分によっては片方にしか定めがないため、その場合は `absent` に理由を書きます（本文と `absent` の両方に同じ program を書くとエラー）。

| 定めがない組み合わせ | 扱い |
| --- | --- |
| 知的障害 × 通級による指導 | `absent` に記載 |
| LD × 特別支援学級 | `absent` に記載 |
| ADHD × 特別支援学級 | `absent` に記載 |

注意点が3つあります。

1. **特別支援学級では自閉症と情緒障害が「自閉症・情緒障害者」という一つの区分**にまとめられ、第一号（自閉症）と第二号（情緒障害）に分かれています。`autism` と `emotional` はそれぞれ該当する号だけを `part` 付きで引用し、`headNote` でその旨を書いています。
2. **通級では肢体不自由・病弱・身体虚弱が「肢体不自由者，病弱者及び身体虚弱者」という一つの区分**です。`physical` と `health` に同じ本文が入ります。
3. **別紙の読点は全角カンマ「，」**です（通知の本文は「、」ですが別紙は「，」）。`validate.mjs` は `text` に「、」が混ざっていたら引用ミスとしてエラーにします。


### 程度別支援には尺度の明示が要る

程度別支援は「確立した尺度があるから段階に意味がある」機能です。尺度のないところに段階を作ると、機能そのものの信頼性が落ちます。

そのため `severity` を持つ疾患には、**必ず `severityScale` を付けてください。**

```json
"severityScale": {
  "name": "GMFCS-E&R（粗大運動能力分類システム 拡張・改訂版）",
  "basis": "academic",
  "sources": ["gmfcs"],
  "note": "段階の名称と定義は日本語版（藤田医科大学）による。…"
}
```

収録している尺度は次のとおりです。**段階の名称と定義は各分類の原文、支援内容は本ツールによる整理**という切り分けを崩さないでください。

| 尺度 | 段階 | 対象 |
| --- | --- | --- |
| GMFCS-E&R | レベルI〜V | 脳性まひ 全4病型 |
| 機能障害度（厚生省研究班，新分類） | ステージ1〜8 | 筋ジストロフィー（デュシェンヌ型等） |
| 小児気管支喘息の重症度分類 | 間欠型〜重症持続型 | 気管支喘息 |
| 凝固因子活性による重症度 | 重症・中等症・軽症 | 血友病、血友病A・B |
| CKDのGFR区分 | G1〜G5（G3はa/b） | 腎臓病、慢性糸球体腎炎 |
| 治療反応性による分類 | 頻回再発・依存性・抵抗性 | ネフローゼ症候群 2件 |
| Ross分類 | クラスI〜IV | 心臓病（先天性・後天性） |
| 大島分類 | 中核群・周辺群 | 重症心身障害 |

### 段階に見えても段階ではないもの

**病型分類を重症度の段階として載せないでください。** 見た目が似ていても別物です。

- **SMA（脊髄性筋萎縮症）のI〜IV型**は、発症時期と最高到達運動機能による**病型の区分**であって重症度の段階ではありません。そのため `severity` は付けず、`note` にその旨と各型の定義を書いています。
- **骨形成不全症のSillence分類**も同様に型の区分です。
- **てんかんの発作頻度**による段階は、確立した分類が存在しません。ILAEが定義しているのは「薬剤抵抗性（適切に選択され使用された2種類の抗てんかん薬で発作抑制に至らないもの）」であって、頻度による区分ではありません。

### 根拠の強さが一様でないこと

`severityScale.basis` は尺度そのものの根拠区分です。`academic` 以外を使うときは、なぜそうなのかを `note` の冒頭に書いてください。画面上のラベルも「用いている尺度」から「目安の立て方」に変わります。

現在 `editorial` なのは次の2つです。

- **Ross分類（心臓病）** — 日本小児循環器学会のガイドラインに「小児ではROSSスコアが用いられてきた」との言及はありますが、**クラスI〜IVの定義を載せた日本語の公式資料が見つかりませんでした**。掲載している定義は英語の二次情報を訳したもので、原典（Pediatr Cardiol 2012）の本文は未確認です。`note` の冒頭に★を付けて明示しています。
- **自閉症＋ADHD（併存）** — DSM-5-TRにそれぞれの重症度はありますが、掛け合わせた段階という分類は存在しません。

### 原文が最新版で取れなかったもの

次の2つは、区分の枠組みは公的資料で確認できたものの、**定義の原文を取れたのが旧版**です。`sources` に旧版と現行版の両方を登録し、`note` にどちらから引いたかを書いています。

| 疾患 | 文言の出典 | 現行版 |
| --- | --- | --- |
| 小児気管支喘息 | 厚労省サイト掲載の表（日本小児アレルギー学会2008年版由来） | JPGL2023（書籍のみ・未確認） |
| 小児ネフローゼ症候群 | 診療ガイドライン2013 語句の定義 | 2020年版（本文に到達できず） |

ネフローゼの「頻回再発」は、**日本の定義（12か月以内に4回以上）とIPNAの定義（12か月間に3回以上）が食い違います。** どちらに拠ったかを必ず明示してください。


- `basis` が `editorial` 以外なら `sources` が1件以上必要
- `basis` が `editorial` のものは、画面で**別の色**になり「目安の立て方」と表示される
- `severityScale` がないまま `severity` を足すと `validate.mjs` が落ちる

現在の収録（8件）:

| 疾患 | 尺度 | basis |
|---|---|---|
| 脳性まひ 4病型 | GMFCS-E&R レベルI〜V | `academic` |
| 重症心身障害 | 大島分類（横地分類・超重症児スコアを注記） | `academic` |
| 自閉症＋知的障害 | 知的障害の程度（DSM-5-TR／ICD-11） | `dsm-icd` |
| 自閉症＋てんかん | 発作頻度による目安 | `editorial` |
| 自閉症＋ADHD | 本ツールによる整理 | `editorial` |

**GMFCS を書き足すときの注意。** 記述は年齢帯（2歳未満／2〜4／4〜6／6〜12／12〜18歳）ごとに異なります。また GMFCS が対象とするのは粗大運動だけで、書字や食事は MACS、意思疎通は CFCS という別の分類があります（公式日本語版の配布元は未特定）。

### 学校生活管理指導表

心疾患や腎疾患の運動制限は、実際には**主治医が学校生活管理指導表に指導区分（A〜E）を記入して学校に渡す**ことで決まります。本ツールの記述ではなく、この書式が現場を動かしています。

そのため対象疾患には `guidanceForm` を付けて印を出しています（27件）。

```json
"guidanceForm": {
  "form": "general",
  "sourceId": "gakko-hoken",
  "ground": "様式本文の「強い運動」の定義に心疾患に関する記載がある"
}
```

**印を付ける範囲は「様式に根拠があるもの」に限っています。** 通常版の様式には対象疾患の一覧がなく診断名は自由記入なので、臨床的に運動制限が要りそうという理由だけでは付けません。`ground`（様式のどこに根拠があるか）は必須で、書かないと `validate.mjs` が落ちます。

| 範囲 | 件数 | 根拠 |
|---|---|---|
| 心疾患 | 12 | 様式本文の「強い運動」の定義に記載 |
| 腎疾患 | 5 | 中学・高校生用の別表に腎臓検診関連の診断区分 |
| 糖尿病 | 4 | 同 糖尿病関連の診断区分（別に糖尿病患児用連絡表もある） |
| アレルギー | 6 | アレルギー疾患用の様式に疾患名が明記 |

腎芽腫は悪性腫瘍で腎臓検診の枠外、糖尿病網膜症は眼合併症のため、印は付けていません。

## 出典区分（各項目がどの資料に基づくか）

疾患・状態495件それぞれについて、医学的説明がどの資料に基づくかを特定し、項目を開くと表示されます。

| 区分 | 意味 | 件数 |
|---|---|---|
| `academic` | 学会・国立研究機関の一般向け解説 | 144 |
| `shouman` | 小児慢性特定疾病 対象疾病 | 127 |
| `editorial` | 対応する公的分類が見当たらず、本ツールが整理した類型 | 81 |
| `mext` | 文部科学省「教育支援の手引」に記載 | 70 |
| `dsm-icd` | DSM-5-TR ／ ICD-11 の診断分類 | 59 |
| `grj` | GeneReviews Japan に日本語解説あり | 14 |
| `research` | 個別の研究発表に基づく | 11 |
| `nanbyou` | 指定難病 | 8 |

**`editorial` は「誤り」ではありません。** 「聴覚過敏が特に顕著なタイプ」「漢字の習得に特化した困難」のように、公的な疾患分類には存在しないが教育実務上は区別する意味がある類型です。81件の大半は自閉症・LD・ADHD・不登校の下位類型で、それぞれ理由を `evidence` に書いてあります。

支援内容は、**どの項目でも `editorial`** です。これはどの資料にも直接書かれていません（自立活動の対応付けは版3.2.0で廃止しました）。

```bash
node basis-audit.mjs                        # 内訳を見る
node basis-audit.mjs --list ld editorial    # 出典を特定できていない項目を並べる
node basis-audit.mjs --set health "重症心身障害" academic ncchd "補足"
```

`validate.mjs` は、`sources` に書かれたIDが `sources.json` に実在するか、`editorial` 以外に出典が付いているか、`editorial` に理由が書かれているかを検査します。
